# 广告模块使用文档

路径：`Card/Assets/App/Ad/`  
命名空间：`App.Ad`

统一激励视频广告链路：调用方只负责「播放一次广告并等待结果」，**只有 `AdWatchResult.Rewarded == true` 才允许发奖**。模块不含任何业务发奖、每日限次或 UI 提示逻辑，这些仍由原业务代码处理。

当前平台支持：抖音通过 `DOUYINMINIGAME` 宏接入 Stark SDK 真实激励视频；编辑器下弹出模拟广告面板，可分别验证「领取奖励领奖」与「关闭不领奖」；微信平台预留宏分支但**尚未接入**，与其他未接入平台一样使用本地模拟（直接视为看完）。

---

## 1. 文件

| 文件 | 职责 | 编译条件 |
|------|------|----------|
| `IAdService.cs` | 广告链路接口、`AdWatchStatus`、`AdWatchResult` | 所有平台 |
| `AdServiceBase.cs` | 播放状态机：防重入、可用性检查、异常兜底、结果收口 | 所有平台 |
| `AdServiceFactory.cs` | 按平台宏创建实现 | 所有平台 |
| `DouyinAdService.cs` | 抖音 Stark SDK 真实激励视频 | `DOUYINMINIGAME && !UNITY_EDITOR` |
| `EditorSimulatedAdService.cs` | 编辑器模拟广告服务：弹面板并把点击结果回传给状态机 | `UNITY_EDITOR` |
| `EditorAdOverlay.cs` | 编辑器模拟广告面板：白色底，中间「领取奖励」领奖，右上角「关闭」不领奖 | `UNITY_EDITOR` |
| `SimulatedAdService.cs` | 本地模拟，直接返回 `Completed`；供微信包等未接入平台使用 | 所有平台 |
| `AdSettings.cs` | 广告位 ID 配置 | 所有平台 |
| `Editor/AdPlatformMenu.cs` | `Build/平台` 菜单一键切换抖音/微信平台宏 | 仅编辑器 |

业务方只依赖 `IAdService`，不要直接实例化或引用具体平台实现。

---

## 2. 平台宏与出包配置

| 构建环境 | 需要定义的宏 | 实际实现 |
|----------|--------------|----------|
| 抖音包 | `DOUYINMINIGAME` | `DouyinAdService`，真实激励视频 |
| 微信包 | `WEIXINMINIGAME` 或 `PLATFORM_WEIXINMINIGAME` | 暂为 `SimulatedAdService`，待接入 |
| Unity 编辑器 | 无需配置，`UNITY_EDITOR` 优先 | `EditorSimulatedAdService`，模拟广告面板 |
| 其他构建 | 不定义上述平台宏 | `SimulatedAdService` |

宏在 `Project Settings → Player → Scripting Define Symbols` 中按目标平台配置，也可以用编辑器菜单一键切换：

- `Build/平台/抖音 (DOUYINMINIGAME)`、 `Build/平台/微信 (WEIXINMINIGAME)`（`Editor/AdPlatformMenu.cs`）。
- 菜单互斥替换 WebGL 平台宏，勾选标记当前平台；其余宏（`DOTWEEN`、`ENABLE_APP_LOG` 等）保持不变，切换后自动触发重编译。

注意：

- **抖音与微信宏出包时必须互斥**。当前工程 WebGL 已配置为抖音（`DOUYINMINIGAME`）；出微信包时需把 WebGL 宏改回 `WEIXINMINIGAME`。
- 不要在同一平台同时定义抖音与微信宏：工厂会优先选择抖音，而项目其它按微信宏编译的代码仍生效，形成混合状态。
- `DouyinAdService.cs` 整文件由抖音宏包裹，微信包和模拟包不会引用 `TTSDK`。
- 编辑器始终使用模拟广告面板，即使意外定义了平台宏也不会触发真实 SDK。

## 3. 配置抖音广告位 ID

在抖音开放平台为小游戏创建**激励视频广告位**，把广告位 ID 填入 `AdSettings.cs`：

```csharp
public const string DouyinRewardedVideoAdUnitId = "你的激励视频广告位ID";
```

抖音激励视频只支持单实例，全游戏共用一个广告位。ID 为空时，抖音真实环境返回 `Unavailable`，不会发奖；本地模拟不受影响。

---

## 4. 注册服务

在 `AppBootstrap.Start()` 中注册，需在业务 ViewModel 解析之前执行：

```csharp
using App.Ad;

_services.Register<IAdService>(AdServiceFactory.Create());
```

工厂按编译宏返回对应实现，业务方不需要判断平台。框架本身不自动注册，也不修改现有启动流程。

## 5. 播放广告

推荐通过构造函数注入 `IAdService`，在按钮命令中等待播放结果：

```csharp
using App.Ad;

private readonly IAdService _ads;

public ExampleViewModel(IAdService ads)
{
    _ads = ads;
}

private async void WatchAdRevive()
{
    var result = await _ads.ShowRewardedVideoAsync();
    if (!result.Rewarded)
    {
        // 按 result.Status 提示；ClosedEarly / Failed / Busy / Unavailable 均不发奖
        return;
    }

    // 广告完整看完，再执行原有业务校验与发奖
    Session.WatchAdRevive();
}
```

### 结果状态

| `AdWatchStatus` | 含义 | 是否发奖 | 建议处理 |
|-----------------|------|----------|----------|
| `Completed` | 完整看完 | **是**（`Rewarded == true`） | 执行原有业务发奖调用 |
| `ClosedEarly` | 用户中途关闭 | 否 | 提示「看完广告才能获得奖励」 |
| `Failed` | 加载或播放失败 | 否 | 提示稍后再试；可用 `ErrorCode` / `ErrorMessage` 排查 |
| `Busy` | 上一次播放未结束 | 否 | 忽略重复点击，无需额外提示 |
| `Unavailable` | 未配置广告位 ID 或广告创建失败 | 否 | 提示广告暂不可用，并检查配置与包环境 |

`IsPlaying` 可用于按钮防连点；`IsAvailable` 可用于界面可用性提示。**不要在 `Failed` / `ClosedEarly` / `Unavailable` 时降级为直接发奖。**

## 6. 平台实现行为

### 抖音（`DouyinAdService`）

- 首次播放时才调用 `TT.CreateRewardedVideoAd` 创建单例，启动期不会产生广告请求。
- `Show()` 后等待 SDK 回调：关闭回调 `isComplete == true` 返回 `Completed`，否则返回 `ClosedEarly`。
- 每次关闭后自动 `Load()` 预加载下一条，缩短下次播放等待。
- 加载或播放失败返回 `Failed`，错误码和错误描述通过 `AppLog`（`LogChannel.Net`）输出。
- 广告创建失败或广告位 ID 为空返回 `Unavailable`；同时只允许一个播放，重入返回 `Busy`。
- 播放过程中的异常由 `AdServiceBase` 统一兜底为 `Failed`，不会留下永久 `IsPlaying` 状态。

### 编辑器（`EditorSimulatedAdService` + `EditorAdOverlay`）

- 播放广告时弹出全屏白色面板：顶部标注「模拟广告（仅编辑器）」，中间「领取奖励」按钮，右上角「关闭」按钮。
- 点「领取奖励」：关闭面板并返回 `Completed`，业务随后发奖。
- 点「关闭」：关闭面板并返回 `ClosedEarly`，不发奖。
- 面板被意外销毁（如停止播放模式）按 `ClosedEarly` 处理，不会悬挂调用方任务。
- 面板置顶显示并拦截下层 UI 点击；无 `EventSystem` 时自动创建。
- 仅编辑器有效，不进任何构建包。

### 本地模拟（`SimulatedAdService`）

- `IsAvailable` 恒为 `true`，`IsPlaying` 恒为 `false`。
- `ShowRewardedVideoAsync()` 立即返回 `Completed`。
- 当前微信包与其他未接入平台使用该实现，因此这些环境的广告行为与接入前一致。

---

## 7. 业务接入原则

1. **先播广告，后发奖**：在原有 `WatchAdRevive`、`WatchAdDoubleGold`、`ClaimAdShopAsync` 等调用之前等待 `ShowRewardedVideoAsync()`。
2. 保留原有业务校验：每日限次、阶段校验、PVP 限制、服务器资料回写等仍由原代码负责。
3. 非 `Rewarded` 结果直接 `return`，不要扣次数、不要关弹窗、不要执行发奖请求。
4. 同一时刻只播放一条激励视频；按钮侧可用 `IsPlaying` 防连点，框架也会用 `Busy` 兜底。
5. 业务方只依赖 `IAdService`，不要添加 `TTSDK` 或平台宏判断。

---

## 8. 后续接入微信平台

微信宏分支已预留在 `AdServiceFactory`，接入时无需改业务调用方：

1. 在 `AdSettings` 增加微信激励视频广告位 ID。
2. 新增 `WeChatAdService : AdServiceBase`，用 `#if (WEIXINMINIGAME || PLATFORM_WEIXINMINIGAME) && !UNITY_EDITOR` 包裹整文件。
3. 实现 `IsAvailable` 与 `ShowRewardedVideo()`：创建微信激励视频并调用 `Show()`；关闭回调按 `isEnded` 调用 `Complete(new AdWatchResult(AdWatchStatus.Completed / ClosedEarly))`，错误回调回传 `Failed`。
4. 把工厂微信分支的 `return new SimulatedAdService();` 改为 `return new WeChatAdService();`。

---

## 9. 验证清单

- 编辑器：弹出白色模拟广告面板；点「领取奖励」返回 `Completed` 并发奖，点右上角「关闭」返回 `ClosedEarly` 不发奖。
- 抖音包：确认只定义 `DOUYINMINIGAME`，并填入真实广告位 ID。
- 真机/开发者工具：完整看完返回 `Completed`；中途关闭返回 `ClosedEarly`；无广告填充或加载失败返回 `Failed`；连续点击只播放一次。
- 未配置广告位 ID 的抖音包返回 `Unavailable`，不会发奖。
- 微信包：当前仍为本地模拟，不会调用微信或抖音广告 SDK。
