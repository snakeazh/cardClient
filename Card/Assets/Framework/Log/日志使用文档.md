# 日志使用文档

路径：`Card/Assets/Framework/Log/`  
命名空间：`Framework.Log`

开发者日志。正式包默认不打 Info/Debug；Editor 和测试包可按模块开关。  
静态门面，**不进 DI**，启动早期（`AppBootstrap`、资源加载）即可调用。

框架总览见 [`框架使用文档.md`](../框架使用文档.md)。  
局内战报（玩家可见）走 `GameSession.Log` / `Run.Log`，**不要**走 `AppLog`。

---

## 1. 文件

| 文件 | 职责 |
|------|------|
| `Runtime/AppLog.cs` | `Debug` / `Info` / `Warn` / `Error` / `Exception` |
| `Runtime/LogChannel.cs` | 模块通道 |
| `Runtime/LogLevel.cs` | `Debug` < `Info` < `Warning` < `Error` |
| `Runtime/LogFilter.cs` | 最低级别 + 通道位掩码 |
| `Editor/LogFilterMenu.cs` | 菜单 `Log/Min Level`、`Log/Channel/...` |

```csharp
using Framework.Log;

AppLog.Info(LogChannel.Level, $"indexed: levels={n}");
AppLog.Warn(LogChannel.Bag, "Failed to parse save data.");
AppLog.Error(LogChannel.Config, "missing row");
AppLog.Exception(LogChannel.Bootstrap, e);
```

Console 点日志会跳到**调用方**（`[HideInCallstack]`），不是 `AppLog` 内部。  
前缀自动是 `[Channel]`，消息里不要再写一遍 `[Level]`。

---

## 2. 三层开关

从外到内，先编译、再打包、最后运行时过滤。

```
AppLog.Info(channel, msg)
  → 编译：无 UNITY_EDITOR 且无 ENABLE_APP_LOG → 调用（含参数）被剥掉
  → 运行：LogFilter（最低级别 + 通道）→ 通过则 Debug.Log
```

| 层 | 做什么 | 正式包 | Editor | 测试 APK |
|----|--------|--------|--------|----------|
| 编译 | `[Conditional]` 标在 `Info` / `Debug` | 调用消失 | 保留 | 有 `ENABLE_APP_LOG` 才保留 |
| 打包 | 是否追加宏 | `Build APK` 不加 | — | `Build APK (Test Logs)` 追加 |
| 运行 | `LogFilter` | 只影响仍编译进来的 Warn | 菜单勾选 | 默认全开，可用 PlayerPrefs |

`Warn` 正式包仍输出到 logcat，可按通道关掉。  
`Error` / `Exception` **始终输出**，不过滤。

---

## 3. 通道

| 通道 | 用在 |
|------|------|
| `Bootstrap` | 启动、Host 落盘异常 |
| `Config` | 配表加载、重复 Id |
| `Game` | 牌面、动画控制器 |
| `UI` | HUD、牌桌、绑定 |
| `Level` | 关卡索引、进度 |
| `Bag` | 背包存档 |
| `Score` | 积分存档 |
| `Atlas` | 图集预载、缺精灵 |
| `Assets` | AssetBundle / 解压 |
| `Save` | 存档（预留） |
| `Talent` | 天赋索引、获得升级、存档 |

新增通道：在 `LogChannel` 末尾加一项，并在 `LogFilterMenu` 加一对 `Log/Channel/名字` 菜单。不要插到中间，以免旧位掩码错位。

---

## 4. 级别

| API | 级别 | 正式包 |
|-----|------|--------|
| `AppLog.Debug` | `LogLevel.Debug` | 剥掉 |
| `AppLog.Info` | `LogLevel.Info` | 剥掉 |
| `AppLog.Warn` | `LogLevel.Warning` | 保留 |
| `AppLog.Error` | `LogLevel.Error` | 保留 |
| `AppLog.Exception` | 等同 Error | 保留 |

`LogFilter.MinLevel` 默认 `Info`：低于它的不打。Editor 菜单改成 Debug 才会看到 `AppLog.Debug`。

`Warn` / `Error` 可带 `UnityEngine.Object context`，Console 会 ping 到该物体。

---

## 5. Editor 菜单

勾选方式和 `Res/Load Mode` 相同，存在 `EditorPrefs`。

| 菜单 | 作用 |
|------|------|
| `Log/Min Level/Debug`～`Error` | 最低级别（单选） |
| `Log/Channel/Enable All` | 打开全部通道 |
| `Log/Channel/Disable All` | 关掉全部通道 |
| `Log/Channel/Bootstrap` 等 | 单通道开关（可多选） |

键：

| 键 | 含义 | 默认 |
|----|------|------|
| `Framework.Log.MinLevel` | `LogLevel` 整型 | `Info` (1) |
| `Framework.Log.Channels` | 通道位掩码 | 全开 |

Editor 用 `EditorPrefs`；真机测试包用同名 `PlayerPrefs`。

## 6. 打包

改菜单：`App/Build/Editor/AndroidBuildMenu.cs`。宏只加在**这一次** `BuildPlayerOptions.extraScriptingDefines`，不写进 `ProjectSettings`（现有 `DOTWEEN` 不受影响）。

| 菜单 | `ENABLE_APP_LOG` | 输出名 |
|------|------------------|--------|
| `Build/Android/Build APK` / `AAB` | 无 | 普通 |
| `Build/Android/Build APK (Test Logs)` | 追加 | 带 `_TestLogs` |

真机测试包 Info 默认全开。要筛模块：改 `PlayerPrefs` 的 `Framework.Log.MinLevel` / `Framework.Log.Channels`（没有 GM 浮层）。

---

## 7. 什么走 AppLog，什么不走

走 `AppLog`：App 与 Framework **运行时** 的诊断输出（启动、配表、资源、关卡、背包、图集等）。

不走：

- Editor 工具（`AndroidBuildMenu`、`ConfigExportMenu`、`ResAssetBundleBuilder` 等）继续 `UnityEngine.Debug`
- 插件（DOTween、TMP）
- 局内战报 `GameSession.Log()` / `Run.Log`

`[Conditional]` 会连插值参数一起剥掉，正式包里 `AppLog.Info(ch, $"x={Heavy()}")` 不会执行 `Heavy()`。`Warn` / `Error` 没有这层保护，参数始终求值。

---

## 8. 注意

- 不要 `Resolve<ILog>`，没有这个服务。
- 不要把 `ENABLE_APP_LOG` 写进 Player Settings，否则正式包也会打 Info。
- 通道枚举只允许在末尾追加。
- 玩家可见文案用 `Run.Log`，不要用 `AppLog` 冒充战报。
