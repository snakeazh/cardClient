# 分享奖励模块使用文档

路径：`Card/Assets/App/Share/`（平台分享能力）、`Card/Assets/App/ShareReward/`（奖励业务）  
命名空间：`App.Share`、`App.ShareReward`

主界面 `ShareRewardItem` → 打开 `ShareRewardPop` → 点 `ShareBtn` 主动拉起小游戏分享面板 →
平台确认分享完成后，**技能「搓牌」使用次数永久 +1**，同时 `ShareRewardItem` 自动隐藏（一次性奖励，入库后永久隐藏）。

## 2. 平台宏与实现

| 构建环境 | 需要定义的宏 | 实际实现 | 分享完成判定 |
|----------|--------------|----------|--------------|
| 抖音包 | `DOUYINMINIGAME` | `DouyinShareService` | 分享面板进出前后台（`TT.GetAppLifeCycle`） |
| 微信包 | `WEIXINMINIGAME` 或 `PLATFORM_WEIXINMINIGAME` | `WeChatShareService` | 转发面板进出前后台（`WX.OnHide` → `WX.OnShow`） |
| Unity 编辑器 | 无需配置，`UNITY_EDITOR` 优先 | `EditorSimulatedShareService` | 模拟面板点「分享成功」 |
| 其他构建 | 不定义上述宏 | `SimulatedShareService` | 无分享能力，`IsAvailable=false` |

- 抖音与微信宏出包时必须互斥，宏切换见 `App/Ad/Editor/AdPlatformMenu.cs`（`Build/平台` 菜单）。
- 编辑器始终使用模拟分享面板，即使误定义了平台宏也不会调用真实 SDK。
- **依赖**：抖音实现依赖 TTSDK（工程当前未入库，整文件由宏包裹，不影响微信/编辑器编译）；微信实现依赖 `Assets/WX-WASM-SDK-V3`。

## 3. 流程

```
Home.ShareRewardItem (Button, UIBind key = ShareRewardItem)
  └─ OpenShareRewardCommand → ShareRewardPop
        └─ ShareBtn (UIBind key = Receive)
              └─ ShareCommand → IShareService.ShareAsync(ShareContent)
                    ├─ Completed  → IShareRewardService.TryClaim() → Toast「搓牌次数永久 +1」→ 关闭弹窗
                    ├─ Cancelled  → Toast「分享未完成，请重新分享」（弹窗保留，可重试）
                    ├─ Failed     → Toast「分享失败，请稍后重试」
                    ├─ Unavailable→ Toast「当前平台暂不支持分享」→ 关闭弹窗
                    └─ Busy       → 忽略
Mask（点击空白）→ CloseCommand
```

- 分享中 `ShareCommand.CanExecute=false`，等价于防连点；平台侧 `ShareServiceBase.IsSharing` 再兜一层。
- 面板一直不返回时由 `ShareServiceBase.TimeoutSeconds`（微信/抖音 180s）按取消收口，调用方任务不会悬挂。
- 领奖成功后 `ShareRewardService.Changed` 触发 `HomeViewModel.ShareRewardItemVisible` 置 false，
  `HomeView` 用 `Binding.BindActive` 自动隐藏入口，**不需要重开 Home**。

## 4. 分享完成判定（平台能力限制）

### 微信小游戏

微信主动转发接口 `wx.shareAppMessage` **没有成功回调**（官方参数只有
`title / imageUrl / query / imageUrlId / toCurrentGroup / path`，见
[转发文档](https://developers.weixin.qq.com/minigame/dev/guide/open-ability/share/share.html)），
也没有 `onShareAppMessage` 成功事件（该事件只用于被动转发时改卡片内容）。

因此 `WeChatShareService` 的口径是：转发面板把游戏切到后台（`wx.onHide`）后回到前台（`wx.onShow`）即视为分享完成；
兜底逻辑：个别基础库版本转发面板不触发 `onHide` 时，从拉起分享到 `onShow` 间隔 ≥3s 的回到前台也按完成处理。

**已知限制**：用户点开面板后取消返回，同样会触发 `onShow`，客户端无法与“确实转发”区分——这是微信侧接口能力限制。
后续若产品要求严格校验，需要走服务端 + `shareTicket`/群信息校验，不在本模块范围。

### 抖音小游戏

抖音 JS 侧 `tt.shareAppMessage` 有 `success/cancel` 回调，但 TTSDK 的 C# 封装
（`TT.ShareAppMessage(ShareParam)`，`ShareParam = Title/ImageUrl/Query/Extra`）不暴露分享结果，
所以与微信同一口径：`TT.GetAppLifeCycle()` 的 `OnHide` → `OnShow` 视为完成（≥3s 兜底）。

**适配点**：若接入的 TTSDK 版本在 `ShareParam` 上提供 `Success/Cancel` 回调，只需把
`DouyinShareService.BeginShare` 改成「传回调 + 回调里 `Complete`」，状态机与业务层都不用动。

## 5. 永久搓牌 +1 的口径

加成落在账号存档：`ShareRewardService.RubBonusCharges`（未领取为 0，领取后 = `ShareRewardBalance.RubBonusCharges`，当前 1）。

读取入口只有一处：

```csharp
// App/Game/GameDefs.cs → GameBalance
public static int SkillRubUses =>
    (GameConst.DefaultSkillShuffleNum（未加载时 2）) + ShareRewardBonus.RubUses;
```

- 整局首次开打时初始化技能次数（`GameSession.StartStage` → `ResetSkillCharges`，本局后续关卡保留）
  → `GameBalance.SkillRubUses + Run.BonusRubCharges + 词条 - 词缀`；
- 技能按钮上限显示（`GameTableViewModel`）→ 同样走 `GameBalance.SkillRubUses`。

两处共用同一口径，**不要再单独加永久加成**，否则按钮上限和实际次数会不一致。

**PVP**：PVP 基础次数读 `GameConst.PVPDefaultSkillShuffleNum`（服务端 `PvpMatch`/`PvpSkillShop` 口径），
对局搓牌次数由服务端快照 `f.RubLeft` 下发（`GameSession` 直接回写 `Run.PeekGoodCharges`），
本地永久加成不参与 PVP 次数计算；如后续需要 PVP 也享受，需要服务端下发或协议加字段。

## 6. 存档

键：`sharereward.v1`，`JsonUtility` 序列化 `ShareRewardSaveData`：

| 字段 | 说明 |
|------|------|
| `Claimed` | 是否已领取（true → 首页入口永久隐藏） |
| `RubBonusCharges` | 已发放的永久搓牌次数加成总量（当前 0 或 1） |

`ShareRewardService` 实现 `ISaveFlushable`，由 `AppServicesHost` 在切后台/退出时自动落盘；
`TryClaim()` 内立即 `Save()` 刷盘，避免分享成功后被强杀丢奖励。

## 7. 调试

- 编辑器 Play：点 `ShareRewardItem` → `ShareBtn` 弹出模拟分享面板，面板上会显示本次下发的标题/图片/query；
  「分享成功」走领奖流程，「取消分享」验证提示与弹窗保留逻辑。
- `Debug/外挂/重置分享奖励（可重新领取）`：清空领取记录，`ShareRewardItem` 立即重新显示。
- 确认加成：开局后技能栏搓牌上限 = `GameConst.DefaultSkillShuffleNum + 1`；
  日志 `[SkillCharges]` 与 `[ShareReward]` 分别记录次数口径与领奖。

## 8. 已知限制 / 后续

1. 微信取消分享无法与成功区分（见第 4 节），需要严格校验时走服务端。
2. 抖音实现按 TTSDK 6.x 文档（`TT.ShareAppMessage(ShareParam)` + `TT.GetAppLifeCycle()`）编写；
   工程未包含 TTSDK，抖音包编译前需先接入 SDK，并用 `Build/平台/抖音` 切换宏验证。
3. 奖励数值暂为代码常量（`ShareRewardBalance`），策划上表后可改读 `GameConst`（同 `TTRewardBalance` 口径）。
4. 分享文案/图片直接写在 `ShareRewardBalance`；如需按活动配置，后续接配置表。
